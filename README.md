# JARVIS — Digital Clone of Anas (Hybrid RAG)

> **⚠️ Notice:** This is an AI digital clone of **Anas**, not the real person. All responses are strictly grounded in authentic documents, curriculum vitae, technical project write-ups, engineering philosophies, and first-person FAQ records authored by Anas. If a query falls outside the retrieved evidence, the clone truthfully replies: *"I don't have that in my notes."*

---

## 1. Project Overview & Architecture
This repository implements an interactive, truthful Retrieval-Augmented Generation (RAG) conversational clone representing **Anas**, a BS Computer Science undergraduate at the University of Management and Technology (UMT) Sialkot, Founder & CEO of Atarion Solutions, and Vice President of the Computer Science Society.

The system features:
1. **Lexical Keyword Retrieval (BM25)**: Evaluates exact keyword matches using `rank_bm25.BM25Okapi` on tokenized text chunks.
2. **Dense Semantic Retrieval**: Computes cosine similarity via NumPy using precomputed 384-dimensional embeddings (`embeddings.npy`) generated by `sentence-transformers/all-MiniLM-L6-v2`.
3. **Hybrid Ranking via Reciprocal Rank Fusion (RRF)**:
   $$\text{RRF}(d) = \sum_{m \in \{\text{BM25}, \text{Dense}\}} \frac{1}{60 + \text{rank}_m(d)}$$
4. **Persona Generation**: Strict, grounded first-person generation via Hugging Face Inference API (`Qwen/Qwen2.5-72B-Instruct`) with an offline data-driven extraction fallback.
5. **Modern WhatsApp-Inspired UI**: Built with a custom responsive front-end (`static/index.html`) featuring an SVG Arc-Reactor logo, Midnight (cyber blue) and Light themes, collapsible evidence inspector, and zero Gradio styling interference.

## 2. One-Page Evaluation Report

### 2.1 The Knowledge Base: Structure & Rationale
The knowledge base comprises **6 authentic documents** located in the `data/` directory, deliberately curated to cover both factual precision and personal personality:

1. **`bio.md` (Factual Biography)**: Academic trajectory at UMT Sialkot, graduation year (2027), CGPA (3.5), Atarion Solutions leadership, engineering philosophy (correctness first, functionality over decoration), and research focus.
2. **`cv.md` (Curriculum Vitae)**: Structured breakdown of education, roles (Founder & CEO of Atarion Solutions, VP of Computer Science Society), full-stack toolkit (Next.js, React, Node.js, Express, PostgreSQL, MySQL, MongoDB, PyTorch, Hugging Face, FastAPI), client projects, and explicit clarification that no unverified research papers are claimed.
3. **`projects.md` (Long-Form Technical Deep Dive)**: Detailed system designs for signature project **Jarvis** (voice-controlled & chat desktop AI assistant), Atarion products (AI Email Automator, Timetable Management System, Plagiarism Checker, Prompt Injection Shield), PromptShield (5-layer defense API), SAID v2 dataset (280k samples), SPIDER (evaluating 6 small models), and ChaosDB.
4. **`opinions.md` (Personality, Opinions & Society Work)**: Core engineering values, real-world testing philosophy (testing workflows vs. page loads), society event organization (CREATE X 2026, workshops, Agentic AI Hackathon), fitness/boxing habits, and hardware specifications (Ryzen 7 7700X, RTX 3060 12GB + GTX 1060 6GB; laptop i7 13th gen).
5. **`faq.md` (First-Person FAQ)**: 20 direct first-person Q&As in Anas's concise, plain-spoken voice covering identity, CGPA, business direction, research, exam study habits, stress management, and hardware.
6. **`study_and_work_habits.md` (Methodology & Advice)**: Conceptual learning habits, assignment writing guidelines (humanized, concise, no decoration/emojis), project lifecycle execution, daily routine (10 PM - 5 AM sleep), and decision-making framework.

**Rationale for Chunking**:
Documents are partitioned into overlapping chunks of **150 to 350 words** with a **40-word overlap** (and minimum trailing chunk threshold of 80 words). This produces 13 high-density chunks that:
- Preserve complete contextual paragraphs without splitting critical project architectures.
- Overlap prevents boundary cutoff of critical sentences.
- Enable top-3 chunks to fit within the prompt context without truncation.

### 2.3 Failure Case Analysis
- **Query**: *"What are your thoughts on using Rust for building high-speed network proxies?"*
- **Observed Behavior**: The clone retrieved chunks discussing Python, C++, Linux, networking, and system design, replying:
  > *"I don't have that in my notes."*
- **Root Cause**: While the persona honestly admitted its lack of specific notes, BM25 matched on generic tokens like *"network"* and Dense matched on *"high-speed / proxy"*, consuming top-k context slots with tangential information.
- **Why It Happened**: Dense embeddings map related technologies (C++, Rust, networking, backend architecture) close together in semantic space. When a query references a technology not present in the knowledge base, dense retrieval pulls the nearest semantic neighbor rather than acknowledging zero match.

### 2.4 Planned Future Improvements
1. **Dynamic Score Thresholding & Rejection**:
   Introduce a minimum Cosine similarity / RRF cutoff. If the top candidate falls below $\tau = 0.32$, bypass the LLM entirely and immediately return *"I don't have that in my notes."*, reducing latency and API usage.
2. **Context-Aware Query Rewriting (HyDE / Multi-Query)**:
   In multi-turn conversations, follow-up queries with pronouns (e.g., *"What did you use for layer 3?"*) degrade retrieval. Adding a lightweight query-rewriter to resolve co-references from chat history would improve multi-turn retrieval.
3. **Cross-Encoder Reranking at Scale**:
   While BM25 and Bi-Encoder embeddings are fast ($O(1)$ lookup / matrix multiplication), passing top-10 merged candidates through a Cross-Encoder (`ms-marco-MiniLM-L-6-v2`) computes full cross-attention between query and passage, eliminating false-positive lexical matches.

---

### 2.5 Hybrid Fusion Comparison: RRF vs. Weighted Fusion
- **Reciprocal Rank Fusion (Implemented Default)**:
  RRF is rank-based ($\frac{1}{60 + \text{rank}}$). It operates independently of score distributions and variance between BM25 (unbounded positive scores) and dense cosine similarity (bounded $[-1, 1]$), eliminating the need for empirical score calibration.
- **Weighted Score Fusion (Alternative)**:
  $$\text{Score}_{\text{weighted}} = \alpha \cdot \text{Norm}(\text{Dense}) + (1 - \alpha) \cdot \text{Norm}(\text{BM25})$$
  While weighted fusion allows fine tuning (e.g. prioritizing BM25 for rare technical names), it requires min-max normalization across query batches and is sensitive to score outliers. Both methods are available in `rag.py`.

## 4. Deploying to Hugging Face Spaces

1. Create a new Space on [Hugging Face](https://huggingface.co/new-space) with the **Gradio** SDK.
2. Initialize and push your repository:
   ```bash
   git init
   git remote add origin https://huggingface.co/spaces/<your-username>/<your-space-name>
   git add .
   git commit -m "Deploy JARVIS Digital Clone"
   git push -u origin main
   ```
3. In your Space's **Settings > Variables and secrets**, add `HF_TOKEN` with a Hugging Face Access Token to activate full 72B inference generation.
